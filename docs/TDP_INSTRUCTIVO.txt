1. PREPARAR LA COMPUTADORA
--------------------------
Instalar git, una distribucion de LaTeX (TeX Live o MiKTeX) y Claude Code. Despues:

    git clone -b claude/home-41-piper-mission https://github.com/ShiiSuii/base_athome.git
    cd base_athome
    git pull
    mkdir -p tdp
    git clone https://github.com/RoboCupAtHome/TDPTemplate.git tdp/template
    claude

Usar esa rama: el trabajo reciente no esta en main.
No hace falta ROS ni el robot para escribir. Para medir algo nuevo hay que correrlo en la NUC.

El repositorio es PUBLICO. Antes de subir el TDP o sus figuras, revisar que no tengan datos privados.

6. HONESTIDAD DE LOS RESULTADOS (LO MAS IMPORTANTE)
---------------------------------------------------
No inventar numeros, tasas de exito, participaciones, premios ni integrantes. Si falta un dato,
escribir [FALTA: que dato] y preguntar. Decir siempre en que condicion se obtuvo cada resultado.

  Etiqueta en el repo       Como se puede escribir
  UNIT_PASS / STATIC_PASS   "automated tests cover..." (no es un resultado experimental)
  SIM_PASS                  "in simulation..." (siempre aclararlo)
  NUC/JETSON_VERIFIED       Medido en esa computadora, indicar que se midio y en que condicion.
  HARDWARE_VERIFIED         Unico caso para afirmar que funciona en el robot real.
  PENDIENTE / BLOCKED_*     Solo como trabajo futuro.

Trampas conocidas al 2026-11-04 (volver a verificar):
  - Commander: probado solo en simulacion. Nunca corrio con Nav2 real ni en el robot.
  - Mision "buscar botella y llevarla": en la simulacion liviana el objeto esta fijo respecto del
    robot y la deteccion es simulada. Prueba la logica de la mision, NO la percepcion ni el agarre.
  - Teleop Quest: validada en simulacion. En el brazo real el uso fue parcial; la ultima medida de
    error (102 mm) es anterior a los ultimos arreglos. Hay que volver a medir antes de citarla.
  - Pan-tilt: tiene una falla electrica abierta. Con torque, el U2D2 se cae por USB.
  - Seguir o guiar personas, buscar personas, entregar objetos y responder preguntas: no estan
    implementados en el ejecutor de misiones.
  - El resto de lo que sigue pendiente esta en docs/ROADMAP.md.

Medir antes de la entrega, si llega el tiempo (lo hace el equipo con el robot):
  - N repeticiones de una mision completa con Nav2 real: exitos, tiempo, causas de falla.
  - Agarres reales sobre objetos del reglamento: exitos sobre intentos.
  - Comandos GPSR: porcentaje de plan exacto.
Cualquier prueba con el robot real requiere supervision de una persona. Claude no mueve el robot
ni corre nada contra el desde esta tarea.
